# tools: 플레이 시험

`play-check.js`는 게임을 브라우저로 열어서 "어느 자리에서 시작해, 무엇을 누르고, 무엇을 확인하는지"를 자동으로 해 봐요. 하나라도 실패하면 종료 코드가 1이에요.

## 준비 (한 번만)

```
npm i playwright
npx playwright install chromium
```

Node 18 이상이 필요해요. 저장소에는 `package.json`이 없어요 (실행 환경은 PLAN.md K6에서 정해요).

## 돌리기 (저장소 맨 위 폴더에서)

```
node tools/play-check.js                 전부 (그래픽카드 있는 PC에서 몇 분)
node tools/play-check.js walk,aerial     골라서
node tools/play-check.js --list          시험 목록
node tools/play-check.js fire --headed   창을 띄워서 눈으로 보기
```

그래픽카드가 없는 곳(클라우드):

```
npm i three@0.128.0
SP_THREE=node_modules/three/build/three.min.js node tools/play-check.js --gl=swiftshader --offline
```

- `--gl=swiftshader`: 소프트웨어로 그려요. 초당 1~2장이라 아주 느려요. 전부 도는 데 10분 넘게 걸릴 수 있어요.
- `--offline`: 바깥 주소(글꼴 등)를 막아요. cdnjs가 막힌 곳이면 `SP_THREE`로 three.js 파일을 줘야 해요.
- `SP_WAIT_MS`: 한 번 기다리는 최대 시간(기본 120000). 느린 곳에서는 늘리세요.
- 사진은 `tools/out/`에 저장돼요 (저장소에는 안 올려요).

## 시험 목록

| 이름 | 확인하는 것 |
|---|---|
| panel | 첫 화면에 혼자 / 아무 방이나 / 방 만들기 / 코드 입력이 스크롤 없이 보임 (1280×800) |
| phone | 폰 크기(390×844)에서 옆으로 안 넘치고, 혼자 있기로 들어가짐 |
| solo | 혼자 있기: 방 없음, 다른 사람 0명, 소리 엔진 켜짐 |
| walk | W로 걸으면 움직이고 발자국이 남음. 바닥을 클릭해도 안 걸음 (도윤 결정) |
| look | 화면 가운데 12곳이 3D 화면에 닿음 (HUD가 마우스를 가로막던 버그), 끌면 시야가 돎 |
| aerial | V로 공중샷, 휠로 높이, V로 돌아옴 |
| fire | E로 불멍, Q로 마시멜로, 탄 걸 먹으면 재 연기. 진짜 소리 엔진도 같이 돌려서 오류를 봄 |
| element | 원소(Cu)를 넣으면 뿌리기 → 불이 휙 커짐 → 원래대로, 불빛에 색 |
| seatLook | 전망 자리에서 끌면 고개가 돌고, 정해진 각도까지만 |
| seats | 해변 벤치는 1인칭(눈사람·글씨 숨김, 눈높이), B로 숨 흔들림 끄고 켜기, 그루터기는 3인칭 그대로. 파도 소리도 같이 돌림 |
| spring | 온천에 몸을 담그면 물 바로 위 눈높이(1인칭), 김이 보이고, 둘레 설산은 온천에서만 보이고 해변에서는 안 그림 |
| rain | 비 오는 숲 정자 벤치는 1인칭, 안개 속 큰 나무 줄기가 보이고, 처마 물방울이 떨어지고, 달은 구름 뒤로 숨음 |
| chimes | 풍경 나무 벤치는 1인칭, 북쪽 하늘 오로라가 나타나 천천히 움직이고, 해변에서는 오로라를 그리지 않음 |
| rooms | 같은 브라우저 탭 4개: 방 만들기, 소문자 코드로 들어가기, 아무 방이나 둘이 만나기, 혼자로 바꾸면 사라지기, 사람 수 누르면 코드 |
| sound | 소리 함수를 `OfflineAudioContext`로 그려서 크기(RMS)를 잼. 모닥불(약 0.06~0.09)에 안 묻히는지 |

## 알아 둘 것

- 게임 상태는 `index.html`의 `window.__soft`(시험 손잡이)로 읽어요. 거기 있는 이름을 바꾸면 이 파일도 같이 고치세요.
- 정해진 초만큼 기다리지 않고, 게임 상태가 될 때까지 기다려요(`until`). 그래서 느린 컴퓨터에서도 결과가 같아야 해요.
- `sound`는 귀로 듣는 시험이 아니에요. "소리가 나는지, 너무 작아지지 않았는지"만 알아요. 기준 숫자는 2026-11-22에 잰 값의 약 60%라서, 소리를 일부러 줄이면 기준도 같이 고쳐야 해요.
- `rooms`는 같은 브라우저 탭끼리 만나는 시험 모드만 확인해요. Firebase 진짜 연결은 확인하지 않아요 (PLAN.md K3).
- 속도(FPS)는 재지 않아요. 그건 PLAN.md K1이에요.
